# The move to io-http 0.8

io-http went from 0.7 to 0.8, pimalaya-stream from 0.3 to 0.4 and the dev-dependency io-oauth from 0.6 to 0.7, itself on io-http 0.8 and pimalaya-stream 0.4, so one copy of each stays in the graph. The only move of these releases is in pimalaya-stream: `tls::Tls` holds the trusted certificate under `server` (a `TlsServer { cert }`) instead of `cert`, and gained `client`, the certificate presented for mutual TLS. io-http 0.8 and io-oauth 0.7 only follow it.

No code changed: the crate never reads the fields of `Tls`, it passes `GtasksClientStdConnectOptions::tls` through, and the live suite builds `Tls::default()`. The bump is still breaking for a caller, who builds that `Tls` and the `HttpAuthBearer` every coroutine takes from the new releases. The live suite was built, not run.

No change folder: the bump is three version requirements and the lockfile.

Capabilities moved: none.
