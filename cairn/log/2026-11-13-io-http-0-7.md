# The move to io-http 0.7

io-http went from 0.6 to 0.7 and the dev-dependency io-oauth from 0.5 to 0.6, itself on io-http 0.7, so one copy of io-http stays in the graph. Nothing stopped compiling: the live suite mints its token through the JWT bearer client of io-oauth, whose surface it uses did not move. The live suite was built, not run.

Three items the family audit of 2026-11-13 left for this bump came with it.

**A request that would split is a refusal of this crate.** io-http 0.7 fails the first resume of `Http11Send` when a method or a header name is not a token, or when a header value holds CR, LF or NUL. That reached a caller as `GtasksSendError::Send(Http11SendError::InvalidRequest(_))`, beside the transport failures. It now reads as `GtasksSendError::InvalidRequest`, the variant an id or an etag is already refused with, so one variant means "nothing was sent". Its message names the header, never its value. Seen with the token `fake-token`, CR LF, `X-Injected: 1`: on io-http 0.6 the first resume asked to write a request holding the line `X-Injected: 1`; on 0.7 before the mapping it completed with `Send(InvalidRequest(InvalidHeaderValue("Authorization")))`. The check of the etag in `GtasksSend::with_guard` stays: it is wider (every ASCII control character) and fails when the coroutine is built.

**`api_url` is a wrapper over `http_url_build` (FAM-11).** The helper of io-http has the body `api_url` had: the same base handling, the same per-segment encoding, the same refusal of an empty segment, a dot segment and a segment holding a tab or a line break. No request the tests pin moved. `HttpUrlBuildError::InvalidSegment` maps to `GtasksSendError::InvalidRequest` with the message it had, `InvalidBaseUrl` to `GtasksSendError::ParseUrl`, which the constant base never reaches.

**The trace log leaves the query out.** The send path logged the whole request URL at trace level. It now logs the scheme, the host and the path.

No test changed; one was added, `refuses_a_token_holding_a_line_break` in tests/send.rs. No change folder: the bump is one mapping and one wrapper.
