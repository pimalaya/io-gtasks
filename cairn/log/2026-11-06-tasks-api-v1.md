# Mirror the Google Tasks API v1

Created io-gtasks from io-gcal's layout, on the Android app's request (2026-11-06) and as the first step of unfog's google-tasks change. The surface was checked against the discovery document, revision 20261103: tasklists (list, get, insert, update, patch, delete) and tasks (list, get, insert, update, patch, delete, move, clear). Writable fields are `GtasksField` tri-states, borrowed from io-msgraph's `MsgraphField`, so the VTODO read back by `from_ical` patches the mapped fields only, as the Android app asked; path segments are percent-encoded one by one rather than joined.

Probed live on 2026-11-06 with the pimalaya-510315 service account, then locked in tests/google.rs, green on the service account and on google@pimalaya.org through domain-wide delegation (the tasks scope is already granted there, and the Tasks API already enabled on the project):

- a JSON `null` clears `notes` and `due` on a patch; a null `title` becomes the empty string;
- `If-Match` is honoured on task PATCH, PUT and DELETE (412, `failedPrecondition` or `conditionNotMet`) and ignored on task list PATCH and PUT, which overwrite (200);
- `parent` in a task patch is ignored silently; an `id` in an insert body is ignored, the server assigning its own;
- `due` keeps the UTC day of the timestamp given (`2026-11-10T23:30:00-05:00` became `2026-11-11T00:00:00.000Z`); a bare date is refused with 400;
- completing without `completed` stamps now; reopening drops `completed` whatever the write says; completing a parent completes its subtasks; deleting a parent deletes its subtasks, which keep their `parent`, while a subtask deleted on its own loses it;
- a deleted task is returned by `tasks.get` and by `updatedMin` plus `showDeleted`, and patching `deleted` to false restores it; retention was not observable within the session;
- a move to another list keeps the id and leaves no trace in the source list, even with `showDeleted` and `showHidden`;
- `tasks.clear` hides the completed tasks (`hidden` true) and moves their position;
- a task list's `updated` moves on a task insert but not on a task patch.

Capabilities moved: api (ADDED), ical (ADDED), sync (ADDED).
